 You should switch to a true transit state machine (reserve edge now, arrive later) and stop mutating hub/link counts in mixed ways.

   1. Initialize occupancy correctly
  In Graph.__init__, set self.start.size = self.drone_num after creating drones (or before, consistently).
   2. Add a transit state
  Replace overloaded WAITING logic with:
    - READY
    - IN_TRANSIT
  (Optional: a separate blocked/wait state, but not required.)
   3. Reserve on choose, don’t teleport (choose_zone)
  Only when capacity allows:
    - connection.size += 1
    - self.zone.size -= 1 (leaving source hub)
    - self.destination = connection
    - self.remaining_turns = 2 if connection.hub.zone == "restricted" else 1
    - self.state = IN_TRANSIT
  If blocked, do nothing except stay READY (retry next turn).
   4. Move only transit drones (move_drone)  
    - If not IN_TRANSIT: return
    - remaining_turns -= 1
    - If still > 0: return
    - On arrival:
     - self.zone = self.destination.hub
     - self.zone.size += 1
     - self.destination.size -= 1
     - self.destination = None
     - self.state = READY
   5. Never decrement edge size unless a drone actually arrives
  Remove the current WAITING branch that decrements destination.size; that’s causing stale-edge corruption.
   6. Main loop order
  Per turn:
    - Phase A: for drones with state == READY and not at finish → run dijkstra + choose_zone
    - Phase B: for all drones → move_drone()
  Don’t skip move solely because zone == finish; skip based on state.
   7. Keep destination cleared after arrival
  This avoids stale reservations affecting later turns.
   8. Note on map errors
  Your easy/02_simple_fork and medium/03_priority_puzzle are currently invalid by parser rules (start/finish max_drones < nb_drones), independent of algorithm logic.

  These changes will eliminate negative hub sizes, stuck link reservations, and most loop/stall behavior.
